# Инструкция по запуску сайта ООО «АРЕАЛ-ПРОМ» на хостинге

Документ описывает полный путь: от проверки сайта на компьютере до публикации на GitHub и размещения на хостинге.

## 1. Состав сайта

Сайт сделан как статический проект. Для его работы не нужен Node.js, база данных или серверная сборка. Достаточно любого хостинга, который умеет отдавать HTML, CSS, JS, JSON, SVG и PDF.

Основные файлы:

- `index.html` — главная страница.
- `privacy.html` — политика конфиденциальности.
- `404.html` — страница ошибки.
- `assets/` — стили, скрипты и изображения.
- `content/` — редактируемые данные услуг, объектов и документов.
- `docs/` — PDF-файлы документов компании.
- `robots.txt` и `sitemap.xml` — файлы для поисковых систем.

## 2. Локальная проверка перед публикацией

Откройте PowerShell в папке проекта:

```powershell
cd "D:\АРЕАЛ-ПРОМ\02. Бренд и маркетинг\02. Сайт\01. Коды\areal-platform"
```

Запустите локальный сервер:

```powershell
node server.js
```

Откройте в браузере:

```text
http://localhost:8080
```

Проверьте:

- открывается первый экран;
- работает анимация логотипа;
- меню прокручивает к разделам;
- карточки услуг, объектов и документов загрузились;
- форма заявки открывает почтовую программу;
- ссылки телефона, email и Telegram кликабельны;
- страница `privacy.html` открывается;
- сайт удобно выглядит на телефоне.

## 3. Обязательные правки перед запуском

### 3.1. Контакты

В файле `index.html` замените временные значения:

```text
+7 000 000-00-00
info@areal-prom.ru
@areal_prom
Укажите фактический адрес офиса
```

Телефон в ссылках `tel:` нужно писать без пробелов, скобок и дефисов:

```html
<a href="tel:+78120000000">+7 812 000-00-00</a>
```

### 3.2. Домен

После покупки домена замените `https://example.com/` в файлах:

- `index.html`;
- `robots.txt`;
- `sitemap.xml`.

Например:

```text
https://areal-prom.ru/
```

### 3.3. Документы

В папке `docs/` сейчас лежат файлы-заглушки. Перед публикацией замените их на реальные PDF:

- `requisites.pdf` — реквизиты;
- `company-card.pdf` — карточка компании;
- `certificates.pdf` — СРО, сертификаты или временный информационный PDF.

Если меняете имена файлов, обновите ссылки в `content/documents.json`.

### 3.4. Объекты

Карточки объектов редактируются в `content/projects.json`.

Пример одной карточки:

```json
{
  "title": "Название объекта",
  "region": "Санкт-Петербург",
  "status": "выполнено",
  "description": "Краткое описание работ."
}
```

### 3.5. Услуги

Услуги редактируются в `content/services.json`. У каждой услуги должны быть:

- `id` — уникальный идентификатор латиницей;
- `title` — название;
- `description` — короткое описание;
- `works` — список работ.

## 4. Подключение формы заявки

Сейчас форма работает как безопасный статический вариант: после заполнения она открывает почтовую программу пользователя и формирует письмо на `info@areal-prom.ru`.

Для полноценной отправки заявок без почтовой программы нужно подключить один из вариантов.

### Вариант A. Скрипт на хостинге

Подходит для обычного PHP-хостинга.

1. Создать файл `send.php`.
2. Настроить отправку письма на корпоративную почту.
3. В `assets/js/main.js` заменить `mailto:`-логику на `fetch('/send.php')`.
4. Добавить защиту от спама и ограничение частоты отправки.

### Вариант B. Netlify Forms

Подходит, если сайт размещается на Netlify.

1. Добавить атрибуты `name="request"`, `method="POST"`, `data-netlify="true"` в форму.
2. Добавить скрытое поле `form-name`.
3. Опубликовать сайт на Netlify.
4. Проверить заявки в панели Netlify.

### Вариант C. Внешний сервис

Можно использовать Formspree, Getform или аналогичный сервис.

1. Зарегистрировать форму в сервисе.
2. Получить endpoint.
3. Отправлять данные формы через `fetch` в `assets/js/main.js`.
4. Проверить доставку заявок на почту.

## 5. Подключение Яндекс Метрики

1. Зайдите в Яндекс Метрику.
2. Создайте счетчик для домена сайта.
3. Скопируйте код счетчика.
4. Вставьте код в `index.html` перед закрывающим тегом `</head>`.
5. При необходимости вставьте код также в `privacy.html` и `404.html`.
6. В Метрике настройте цели:
   - отправка формы;
   - клик по телефону;
   - клик по email;
   - клик по Telegram;
   - скачивание документов.

## 6. Загрузка проекта на GitHub

Если репозиторий уже связан с GitHub, выполните:

```powershell
git status
git add .
git commit -m "Build Areal Prom corporate website"
git push origin main
```

Если репозиторий еще не создан на GitHub:

1. Зайдите на GitHub.
2. Создайте новый репозиторий, например `areal-platform`.
3. Не добавляйте README на GitHub, если он уже есть локально.
4. Скопируйте URL репозитория.
5. В папке проекта выполните:

```powershell
git remote add origin https://github.com/USERNAME/areal-platform.git
git branch -M main
git add .
git commit -m "Build Areal Prom corporate website"
git push -u origin main
```

Если GitHub попросит авторизацию, используйте GitHub Desktop, GitHub CLI или personal access token.

## 7. Варианты хостинга

### Вариант A. Обычный виртуальный хостинг

Подходит для большинства российских хостингов.

1. Зайдите в панель хостинга.
2. Откройте файловый менеджер.
3. Перейдите в папку сайта, обычно это `public_html`, `www` или папка домена.
4. Загрузите содержимое проекта, а не саму папку проекта.
5. Убедитесь, что `index.html` лежит в корне сайта.
6. Включите SSL-сертификат в панели хостинга.
7. Проверьте сайт по HTTPS.

В корне хостинга должны оказаться:

```text
index.html
privacy.html
404.html
assets/
content/
docs/
robots.txt
sitemap.xml
```

### Вариант B. GitHub Pages

Подходит для временной демонстрации или простого статического сайта.

1. Загрузите проект в GitHub.
2. Откройте Settings репозитория.
3. Перейдите в Pages.
4. В разделе Build and deployment выберите:
   - Source: Deploy from a branch;
   - Branch: `main`;
   - Folder: `/root`.
5. Нажмите Save.
6. Дождитесь публикации.

Минус GitHub Pages: для коммерческого сайта с формами и почтовыми заявками все равно понадобится внешний сервис формы или отдельный backend.

### Вариант C. Netlify

Удобно для статических сайтов и форм.

1. Зарегистрируйтесь на Netlify.
2. Нажмите Add new site.
3. Подключите GitHub-репозиторий.
4. Build command оставьте пустым.
5. Publish directory укажите `.`.
6. Нажмите Deploy.
7. Подключите домен и SSL.

### Вариант D. Vercel

Подходит для статического сайта, но формы нужно подключать отдельно.

1. Зарегистрируйтесь на Vercel.
2. Импортируйте GitHub-репозиторий.
3. Framework Preset выберите Other.
4. Build Command оставьте пустым.
5. Output Directory укажите `.`.
6. Нажмите Deploy.

## 8. Подключение домена

1. Купите домен или используйте уже существующий.
2. В панели хостинга добавьте домен.
3. У регистратора домена пропишите DNS-серверы хостинга или нужные DNS-записи.
4. Дождитесь обновления DNS. Обычно это занимает от 15 минут до 24 часов.
5. Включите HTTPS/SSL.
6. Проверьте открытие сайта по адресам:
   - `https://ваш-домен.ru/`;
   - `https://www.ваш-домен.ru/`, если используется `www`.

## 9. Проверка перед запуском

Перед публикацией проверьте:

- везде указаны реальные контакты;
- форма заявки отправляет обращение нужным способом;
- документы скачиваются и открываются;
- домен заменен в `robots.txt`, `sitemap.xml`, canonical и Open Graph;
- подключена Яндекс Метрика;
- сайт открывается по HTTPS;
- мобильная версия не ломается;
- нет временных текстов и заглушек;
- поисковая индексация не закрыта в `robots.txt`.

## 10. Как обновлять сайт после запуска

### Изменить услугу

Откройте `content/services.json`, измените текст, сохраните файл и загрузите обновление на хостинг или отправьте изменения в GitHub.

### Добавить объект

Откройте `content/projects.json`, добавьте новый объект по примеру существующих карточек. Следите, чтобы JSON оставался валидным: запятые между объектами обязательны, после последнего объекта запятая не ставится.

### Добавить документ

1. Загрузите PDF в `docs/`.
2. Добавьте запись в `content/documents.json`.
3. Проверьте ссылку на сайте.

### Изменить контакты

Контакты сейчас находятся в `index.html`. Найдите старое значение и замените его на новое. После изменения проверьте клики по телефону, email и Telegram.

## 11. Рекомендация по дальнейшему развитию

Если сайт нужно будет часто обновлять без работы с файлами, следующим этапом лучше подключить headless CMS или легкую админку. Для такого сайта подойдут:

- Decap CMS с хранением контента в GitHub;
- Netlify CMS/Forms для простого статического сценария;
- WordPress только если нужна привычная визуальная админка и хостинг уже рассчитан на PHP;
- Strapi или Directus, если понадобится более серьезная структура контента.

Для первого запуска текущая статическая версия проще, быстрее и дешевле в сопровождении.
